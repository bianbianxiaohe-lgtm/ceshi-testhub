# Token 节省速查卡（TestHub 协作）

> **原则**：上下文成本 = 你「喂进来」的内容 + 会话长度 + 连接的服务。固定开销（系统提示 / 100+ 技能定义 / 工具定义）压不掉，谁都改不了。
> 本卡只管「省 token」，**与 `docs/REGRESSION.md`（管质量）正交、独立**。

---

## 一、怎么「给路径」（最常问）

不用手打文件内容。按你要让我看的东西，选对应的给法：

| 你要让我看的东西 | 怎么给 | 示例 |
|---|---|---|
| 代码文件 / 某个函数 | 绝对路径（可加 `:行号` 或函数名） | `C:\testhub\apps\requirement_analysis\views.py:1646` 或 `ai_model_service.py 的 generate_test_cases_stream` |
| 短报错（栈跟踪，< ~50 行） | **直接贴**，很便宜 | 贴 `Traceback` 那几行即可 |
| 长日志 / 整文件 / 大段 dump | 存成文件，给绝对路径 | 存 `C:\Users\Administrator\Desktop\err.log`，说「看这个」 |
| 截图（UI 问题位置） | 直接贴图，或存盘给路径 | 截图存 `C:\Users\Administrator\Desktop\shot.png`，说「问题见此图」 |
| 已记录的 bug | 引编号 | 「BUG-03 又出现了」（AI 查 REGRESSION.md 即知位置） |

**关键纠正**：
- 截图 / 短报错 **直接贴就对了**，别用几百字文字描述截图内容（那才费 token）。
- 只有「整文件代码 / 超长日志（几百行以上）」才需要存盘给路径，避免把全文灌进上下文。
- 报错不都有日志：代码/运行时错误有 Traceback（短，可贴）；UI 问题靠截图。按问题类型选介质。

**改代码时不知道路径？完全不用给——而且「自然语言描述功能+症状」就是最优输入，不是退而求其次。**
- 你只用大白话讲清**哪个页面/功能、出了什么症状、预期 vs 实际**，AI 负责 `grep` 定位代码在哪，你零路径成本：
  - 例：「详情页点『下一步』应该回用例列表，现在退回项目首页了」→ AI grep 「下一步/返回/路由」定位到对应视图/组件，读那一段，改。
  - 例：「BUG-01 流式生成又崩了」→ 查 `REGRESSION.md` 即知在 `ai_model_service.py` 的 `generate_test_cases_stream`，直接修。
- 描述越具体（哪个页面 + 什么操作 + 预期 vs 实际），AI 定位越快、越少绕路 → 越省 token。你**完全不用**做「翻代码找位置」这个中间步骤。
- 已知 bug → 直接说编号（BUG-03 等），AI 查台账即知文件+函数。
- 新功能 → 说清「改哪个模块、做成什么、注意什么」即可，例如「把 api_agent 的导入逻辑改成支持批量，别动 requirement_analysis」。
- 只有当你**本来就清楚**文件位置时，给路径能让我少搜几步（省一点点），不给也完全没问题。

## 二、你能控制的省 token 动作（按收益排序）

1. **给路径 / 贴图，不贴整文件代码**。
2. **不同任务开新会话**，别一个会话干一周——旧会话的工具结果（grep 大段、编译输出）持续占上下文。
   - CodeBuddy VSCode 插件：对话面板左上角点 **`New Task`（或 `+` / 新建对话）** 即清空上下文；或输入框打 **`/clear`** 清当前会话；**History** 按钮管旧会话（不点不加载）。每个不同任务点一次 New Task。
   - **清的是「对话上下文」**：你的消息 + 我的回复 + 工具结果（grep 大段、编译输出、读过的文件内容）。模型只看「系统提示(固定小头) + 你新发的这条」，旧 token 不计入。
   - **不丢的**：磁盘文件（REGRESSION.md / TOKEN-SAVING.md / 代码改动）、项目记忆（CODEBUDDY.md / 记忆文件）。所以新会话照样读得到背景，只是忘了刚聊的闲天——那本该忘。
   - **History 里还能找回旧会话**（点击即重新加载），但为省 token 别回点，要续就开新的。
   - **新会话后 AI 要「重新熟悉代码」吗？——不会，成本极小：**
     - AI 本就没有「熟悉代码」的状态，它每次只处理「你给的上下文」。所谓「熟悉」是旧会话里你攒出来的长上下文；新会话丢掉的正是那笔**累积债**，不是知识。
     - 新会话里改代码：AI 用 `grep` 定位你要改的那**一个**函数 → 只读那几十行（不会把 2300 行的 `ai_model_service.py` 读一遍）→ 用 `Edit` 局部改。按需、局部、可控。
     - 背景（架构 / 端口 / 已踩坑）在 `CODEBUDDY.md` / `REGRESSION.md`，你派活时我才读这几 KB，比你每次手打一遍 TestHub 背景省得多。
     - **算账对比**：新会话「重新熟悉」= 局部 grep + 读背景卡 ≈ 几千 token，一次性；旧会话干一周 = 前面所有 grep 输出 / 编译结果 / 长报错持续占着上下文、每次发消息都重算，累积到几万 token 且越来越慢越贵。**新会话总账更省，而且更精准**（不背着一堆无关工具结果干扰）。
3. **断开不用的 MCP / 插件**（当前仅 `agent-mail` 连着，已较干净；只有真要用的才连）。
4. **关掉不用的编辑器标签**——打开的文件自动进上下文。
5. **指令收窄**：「只改这个函数」，别让 AI 读整个模块（如 2300 行的 `ai_model_service.py`）。
6. **背景卡已就位**：结构 / 端口 / 已踩坑都写在 `CODEBUDDY.md`，指向它即可，别每次重述 TestHub 背景。

## 三、AI 默认行为（已承诺，无需你提醒）

- 要文件 → 直接 `Read`，**不让你贴**。
- 改代码 → 用 `Edit` 局部改，**不重写整文件**（重写会把全文再发一遍）。
- 回复尽量短，不灌水。
- 能 `grep` / `Read` 定位就不全量读模块。

## 四、你自己的 LLM 管线（Modao skill 等 9 次调用）

省的是你平台调 LLM 的钱，不是聊天 token，但目的一样：
- **RAG**：只取 top-k 片段，替代整本注入。
- **结果缓存**：稳定输入（YApi 规范、API schema）命中即返回。
- **分层模型**：分类 / 抽取 / 清洗等简单子任务用小模型。
