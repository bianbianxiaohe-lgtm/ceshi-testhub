# 团队开发环境接入指南

> 最后更新：2026-10-10 · 适用版本：后端镜像分层启用之后（基础镜像 `testhub-backend-base:20261010`）

本文面向**刚拉下代码的同事**。目标是让你在最短时间内把 TestHub 跑起来，并且**和团队共用同一套开发数据库**（不用自己造数据）。

---

## 0. 先搞清楚：共用的是什么

| | 说明 | 地址 |
|---|---|---|
| **共享开发库** | MySQL 8.0，库名 `testhub_dev` | `192.168.8.75:13306` |
| **Redis** | 各人本地（无共享必要） | 本地容器 |
| **上传文件 `media/`** | ❌ **不共享**，各自本地卷 | — |
| **账号** | `testhub_dev` | 密码问负责人，取自他机器上 `.env.dev` 的 `DB_PASSWORD` |

⚠️ **生产库是另一套**（主机上的 `testhub-mysql`，库名 `testhub`），**端口没有映射出来**，任何人都不要试图直连它。你连的 13306 是 dev 库。

---

## 1. 前置准备

### 1.1 必须有的软件

- Docker Desktop（Windows/Mac）
- Git
- Node.js 18+（只在你改前端、需要 `npm run build` 时才用）

### 1.2 拿基础镜像（**别跳过，否则你要重装 243 个 Python 包**）

后端依赖（apt 包、ADB、243 个 pip 包、Playwright Chromium）已经被打包进一个基础镜像。从负责人那里拿到 `testhub-backend-base.tar`（约 2.9GB，U 盘/内网共享都行），然后：

```powershell
docker load -i D:\share\testhub-backend-base.tar
docker images | Select-String testhub-backend-base
# 期望看到：testhub-backend-base   20261010   9e52d0175667   2.94GB
```

**为什么这步很重要**：有了它，你本地 `docker compose build backend` 只需复制源码层，**几秒钟**；没有它，pip 要重新解析安装 243 个包，国内网络下大约 **30~40 分钟**，而且容易中途失败。

> 如果版本号不是 `20261010`（负责人重建了基础镜像），重新拿一次新的 tar。

### 1.3 生成 `.env.dev`

仓库里只有模板，不能直接用：

```powershell
cd TestHub
powershell -File scripts/init_dev_env.ps1    # 生成密钥，产出 .env.dev
```

然后把**共享库连接参数**填进去（其余保持脚本生成的默认值）：

```ini
DB_NAME=testhub_dev
DB_USER=testhub_dev
DB_PASSWORD=<负责人给你的密码>
DB_HOST=192.168.8.75      # ← 关键：别再写 mysql
DB_PORT=13306
```

> 注意 `DB_HOST` 写 IP 而不是容器名 `mysql`。写 `mysql` 会连你自己本地起的空库，看到的是"一片空白"，很多人会误以为环境坏了。

## 2. 启动

```powershell
# 首次或代码变更后构建
docker compose --profile app -f docker-compose.dev.yml build backend frontend

# 启动全套（mysql/redis 虽在本地起，但后端实际连的是 192.168.8.75 的共享库）
docker compose --profile app -f docker-compose.dev.yml up -d

# 看后端是否活着（404 = 健康）
curl.exe -s -o NUL -w "%{http_code}" http://localhost:18000/api/
```

访问：

| 服务 | 地址 |
|---|---|
| 前端 | http://localhost:18080 |
| 后端 API | http://localhost:18000 |
| 登录账号 | `admin` / `admin123`（dev 库默认） |

改 Python 代码无需重建：`./apps`、`./backend` 是 bind mount，保存后容器自动生效（改 `urls.py` 例外，需要 `docker restart testhub-dev-backend-1`）。

## 3. 团队约定（**必读**，不遵守会坑到别人）

### 3.1 数据库迁移只能由一个人做

数据库是共用的，**多人同时 migrate 会打架**。约定：

- 由**指定的迁移负责人**统一执行 `python manage.py migrate`
- 其他人拉代码后如果报「表不存在 / 缺字段」，先在群里问，不要自己 migrate
- 新增字段除了写迁移文件，**必须同步在 `docker_start.py` 里补幂等 DDL**，否则别人重启后照样缺列导致 500

### 3.2 `media/` 不共享

你上传的截图、墨刀原型截图、Allure 报告只在你自己机器上。同事看到一个 404 的图片是正常的，不是 bug。需要复现问题时，让对方把文件单独发你。

### 3.3 UI 自动化的设备表是全局的

设备列表存在共享库里。多人同时跑自动化会**互相抢占同一台设备**。跑之前在群里说一声，或者直接插自己的手机。

### 3.4 别提交这些文件

`.gitignore` 已经挡了大部分，但请你别用 `git add -f` 强行加：

- `.env` / `.env.dev`（含真实密码）
- `_db_backup/`（数据库 dump，GB 级）
- `frontend/dist/`、`node_modules/`

## 4. 排障对照表

| 现象 / 报错 | 含义 | 怎么办 |
|---|---|---|
| `ERROR 1045 Access denied for user 'testhub_dev'@'<你的IP>' (using password: YES)` | 账号能被识别，**密码错了** | 找负责人核对 `.env.dev` 的 `DB_PASSWORD` |
| `ERROR 1130 Host '<你的IP>' is not allowed to connect` | 账号不允许从你的 IP 来 | 让负责人在 MySQL 上补 `CREATE USER 'testhub_dev'@'%'` |
| `ERROR 2003 Can't connect to MySQL server` / 连接超时 | 网络不通 | 先问主机是否开机；再让负责人放行防火墙 13306（需限内网段） |
| 能登录但项目列表是空的 | `DB_HOST` 写成了 `mysql` | 改成 `192.168.8.75` 并 `docker compose restart backend` |
| `/api/` 返回 `000` | 后端进程死了 | `docker logs testhub-dev-backend-1 --tail 50` |
| `/api/` 返回 `500` | 大概率缺 migration 或缺列 | 看第 3.1 节，找迁移负责人，别自己 migrate |
| 页面样式/接口是旧的 | 浏览器缓存或 dist 没重建 | Ctrl+F5；前端改了要 `npm run build` |

### 自检连接（推荐第一时间跑）

```powershell
docker run --rm mysql:8.0 mysql -h 192.168.8.75 -P 13306 -u testhub_dev -p<你的密码> -e "select database(), @@hostname;"
```

期望返回 `testhub_dev` 和主机名。

## 5. 什么时候需要重做基础镜像

**只在这三种情况**下需要负责人重做并重新分发 `testhub-backend-base.tar`：

1. `requirements.lock.txt` 变更（加/升级 Python 包）
2. 需要新的系统级依赖（apt 包、ADB 版本等）
3. 升级 Python 基础镜像

负责人操作步骤：

```powershell
python scripts/gen_backend_base.py
docker build -f Dockerfile.backend-base -t testhub-backend-base:<日期> .
# 改 Dockerfile.backend 的 FROM tag → docker compose build backend
docker save testhub-backend-base:<日期> -o D:\share\testhub-backend-base.tar
```

⚠️ **不要手改 `Dockerfile.backend-base`**：它是脚本生成物。改了会导致 Docker 缓存键失配，pip 层全部重跑。唯一事实源是 `Dockerfile.backend-deps`。

改业务代码不需要以上任何操作，`docker compose build backend` 几秒搞定。

## 6. 日常构建与维护速查

| 想做的事 | 命令 |
|---|---|
| 构建后端 | `docker compose -f docker-compose.dev.yml build backend` |
| 重启后端（改了 urls.py） | `docker restart testhub-dev-backend-1` |
| 看后端日志 | `docker logs -f testhub-dev-backend-1` |
| **安全清理 Docker 空间** | `docker image prune -f` |
| 🚫 千万别用 | `docker system prune`、`docker system prune -a`、`docker builder prune`、Docker Desktop 的 Clean / Purge data |

> 最后一条会把「pip 已下载好的包」一起连带清掉，下次构建要重新拉 243 个包。**只用 `docker image prune -f`。**
