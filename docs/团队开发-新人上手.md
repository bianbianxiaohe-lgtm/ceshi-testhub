# TestHub 新人接入（5 步跑起来）

> 说明：我们共用一套**开发环境数据库**（不是生产库），在你机器上跑前后端，数据来自共享库。
> 下面是首次接入的完整步骤，按顺序做即可。遇到问题看最后的对照表。

---

## 0. 前置条件

- Windows + **Docker Desktop** 已装并启动
- 电脑与公司**同一内网**（能 ping 通 `192.168.8.75`）
- Git 已装

---

## 1. 拉代码

```powershell
git clone https://github.com/liuyi61189/my-project.git TestHub
cd TestHub
```

---

## 2. 导入基础镜像（**别跳过，这条省你 30~40 分钟**）

项目后端依赖 243 个 Python 包 + Chromium，直接 `docker compose build` 要下载半个多小时。
我已经把这些依赖打成一个基础镜像，直接导入即可。

> 📦 镜像包 `testhub-backend-base.tar`（约 2.8 GB）—— 找 [负责人] 要（共享盘 / 网盘 / U 盘都行，地址见群公告）

```powershell
docker load -i <你存放的路径>\testhub-backend-base.tar
```

验证一下导入成功：

```powershell
docker images testhub-backend-base
# 期望看到 tag 为 20261010 的镜像
```

---

## 3. 生成本地配置

```powershell
copy .env.dev.example .env.dev
```

然后用记事本（或 VSCode）打开 `.env.dev`，**改这几行**：

```ini
DB_HOST=192.168.8.75        # ← 必改，别留默认的 mysql
DB_PORT=13306               # ← 必改，别留默认的 3306
DB_NAME=testhub_dev
DB_USER=testhub_dev
DB_PASSWORD=<单独发你的密码>  # ← 找 [负责人] 要，不在仓库里
```

再补一个 `SECRET_KEY`，自己生成一个就行（**不要照抄别人的**）：

```powershell
python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"
```

把输出的一长串填到 `.env.dev` 的 `SECRET_KEY=` 后面。

> ⚠️ **不要把别人的 `.env.dev` 整份拷过来** —— 里面有 `SECRET_KEY` 和数据库 root 密码，不该外传。只填上面这几行就够了，其余保持 example 里的默认值。

---

## 4. 启动

```powershell
docker compose --profile app -f docker-compose.dev.yml up -d
```

首次会构建前端和后端业务层。因为第 2 步已经导入了依赖，**这一步只需要几十秒到几分钟**。

看状态：

```powershell
docker compose -f docker-compose.dev.yml ps
# 三个容器都应是 Up / running
```

---

## 5. 验收

浏览器打开 **http://localhost:18080**

用 `admin` / `admin123` 登录。

**成功的判据**：能看到项目列表（当前共 **11 个项目**）。看到数据就说明你本地代码 + 共享库这条链路完全通了。

后端接口单独验证（可选）：

```powershell
curl.exe http://localhost:18000/api/
# 返回 404 是正常的（说明服务活着，只是根路径没路由）
```

## ⚠️ 三条团队约定（请务必看完）

### 1. 数据库迁移由专人负责

大家连同一个库，**不要自己跑 `python manage.py migrate`** —— 多人同时迁移会打架。

你自己新增了模型字段怎么办：**在群里说一声**，由 [负责人] 统一执行迁移。

> 注：本项目新增字段除了写迁移文件，还必须同步改 `docker_start.py` 里的幂等 DDL，两处都要改，漏一处启动就 500。

### 2. `media/` 附件不共享

上传的截图、墨刀原型产出存在**各自的本地卷**里。你传的别人看不到，反之亦然。跑墨刀需求分析时，各自用自己的产物。

### 3. UI 自动化的设备表是全局的

连着的手机/模拟器在库里是全局记录，多人同时跑 UI 自动化会**互相抢占同一个设备**。要跑之前先在群里说一声。

## 出了问题先看这个表

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `2003` / 连接超时 | 网络不通或防火墙没放行 | 确认在公司内网：`Test-NetConnection 192.168.8.75 -Port 13306`；还是不通找 [负责人] 查防火墙 |
| `1045 Access denied ... using password: YES` | 密码写错了 | 核对 `DB_PASSWORD`，注意别多带空格 |
| `1130 Host ... is not allowed` | 你的 IP 不在允许范围 | 找 [负责人] 加账号授权 |
| 能登录但**项目数是 0** | `DB_HOST` 填成了 `mysql`，连到了自己本地空库 | 改回 `192.168.8.75` 并重启容器 |
| 页面打不开 / 容器起不来 | 端口被占用 | 18080/18000/13306 被别的程序占了，改 `.env.dev` 里的 `DEV_*_PORT` |
| 启动时 pip 在疯狂下载 | 第 2 步没做或镜像 tag 不对 | 确认 `docker images testhub-backend-base` 里有 `20261010` |

## 日常开发（接入完成后）

```powershell
# 每天开始
git pull
docker compose --profile app -f docker-compose.dev.yml up -d

# 改了后端代码 → 会自动热重载，不用重启
# 改了前端 → 不需要重新构建镜像（dev 有自己的容器）

# 看后端日志
docker compose -f docker-compose.dev.yml logs -f backend

# 收工
docker compose -f docker-compose.dev.yml stop
```

更详细的说明见仓库内 `docs/团队开发-环境接入.md`。
