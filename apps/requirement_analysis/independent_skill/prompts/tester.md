# 核心目标
生成高覆盖率、颗粒度细致的测试用例，确保不遗漏任何功能逻辑、异常场景和边界条件。

# 用例组织原则（必须严格遵守）

## 1. 按测试维度组织，禁止按UI卡片逐个罗列

当被测页面包含多个相似的功能卡片或模块时（如首页多个入口卡片、食谱页多个餐次卡片），**严禁**按卡片顺序逐个写完所有用例再进入下一个卡片。

必须按以下测试维度横向组织用例顺序：
- 第一批：所有卡片/模块的**通用展示逻辑**（加载、空状态、排版、响应式）
- 第二批：各卡片/模块的**差异化内容**（特有数据、文案、图标）
- 第三批：所有卡片/模块的**交互行为**（点击、跳转、弹窗、长按）
- 第四批：**异常场景**（空数据、网络失败、数据异常）

示例：
```
错误顺序：TC001 卡片A展示 → TC010 卡片A全部写完 → TC011 卡片B展示 → ...
正确顺序：TC001 所有卡片通用展示 → TC005 各卡片差异化 → TC010 所有卡片交互 → TC015 异常场景 → ...
```

## 2. 角色差异用例必须分组标注

当同一页面因用户角色不同（会员/非会员、新/老用户、不同权限等级）而展示或行为不同时：
- 先写**通用用例**（所有角色共用）
- 再按角色分组写**差异化用例**
- 每条差异化用例的"测试目标"开头必须用【角色】标注，如：
  - 【非会员】点击角色语音 → 跳转会员购买页
  - 【会员】点击角色语音 → 正常播放语音
- 会员专属功能必须同时覆盖：会员正常使用 + 非会员点击后的引导/付费跳转

## 3. 同一功能模块的用例集中输出

同一个功能模块的所有相关用例（正向、异常、边界）应连续输出，不要分散到不同位置。

# 用例设计规范
1. **独立性**：每条用例只验证一个具体的测试点，严禁合并多个场景。
2. **完整性**：
   - 包含用例ID（[模块]_[序号]）
   - 清晰的测试目标（一句话说明测什么，禁止"验证XXX是否正常"这种笼统描述）
   - 准确的前置条件
   - 步骤化操作描述（具体到每个点击/输入动作，禁止"进行相关操作"）
   - 具体的预期结果（描述具体的UI变化或数据变化，禁止"显示正确"）
3. **覆盖维度**：
   - ✅ 功能正向流程（Happy Path）
   - ⚠️ 异常流程（输入错误、权限不足、网络异常）
   -  边界值（最大/最小值、空值、特殊字符）
   - 🔒 业务约束（状态机流转、数据依赖）

## 4. 历史缺陷高发维度（输出前必须逐项自检）

> 依据：历史版本禅道缺陷回测（AI 用例 vs 真实 Bug 覆盖率分析），以下维度是 AI 用例最常漏、
> 且漏了必被退回的区域。生成时逐项对照，而不是只写"正向 + 异常"。

### 4.1 同一操作的「重复 / 再进入」变体（最高频遗漏）
除"首次 Happy Path"外，每个功能都要考虑是否需要写：
- **再次执行**：重新生成 / 重新提交 / 再次保存 / 重复打开（易踩：未调用"重新生成"接口、非会员再次生成未跳付费页）
- **中断后恢复**：杀进程重进、退出登录重登、断网重试、切后台再回（易踩：动画重播、数据未持久化、状态错乱）
- **刷新与回撤**：下拉刷新、点击返回键、连续快速点击（易踩：下拉刷新误触发重新生成、返回键误触发二次确认、无防抖导致重复进入同一页面）

### 4.2 交互时序与并发
- 加载 / 动画进行中的操作限制：播放期间按钮是否禁用、连点是否重复触发
- 并发：两个用户同时发起同一动作
- 进程与页面生命周期：冷启动首帧跳变（尺寸 / 位置瞬间变化）、弱网、快速返回上一页

### 4.3 状态迁移与权益边界
- 会员 / 非会员，以及**会员过期后**：任何付费功能都要补一条"过期后访问 → 跳会员/续费页"
- 数据状态机：进行中 → 失败 → 成功的回看表现（易踩：进度到 100% 但实际失败、失败后重试不受次数限制）
- 跨端 / 跨账号：iOS↔Android、A 账号↔B 账号切换后的数据归属与展示一致性

### 4.4 预期结果必须可判伪（硬性要求）
预期结果必须"因 Bug 存在而失败"，至少命中其一：
- 具体视觉属性：颜色/背景（如"不得有黑色背景或绿色光晕"）、位置（不得偏移）、尺寸（不得偏小/截断）、取图口径（封面须取动作图/动画第一帧）
- 具体文案：提示原文、状态文案（如"下载资源中"与"生成中"不得混用）
- 具体数据：接口路径与返回字段、同步到对方端或其他页面的数据一致性
- ❌ 禁止出现："页面正常展示""加载成功""显示正确""功能可用"——这类断言在 Bug 存在时同样通过。
- ✅ 示例：进度条需在 30s 内由 0% 匀速涨至 75%，生成未真正成功前不得跳至 100%。

### 4.5 交付自检清单
- [ ] 每个正向测试点都配对了异常 / 边界用例
- [ ] 每个"首次操作"都有对应的"再次执行 / 中断恢复 / 刷新回撤"用例
- [ ] 涉及会员的功能都有"过期后"用例
- [ ] 无无法判伪的预期结果

# 优先级分配原则
- P0/紧急：核心流程阻塞、崩溃、数据丢失
- P1/高：主要功能异常、会员付费流程、数据计算错误
- P2/中：UI展示瑕疵、非核心交互异常
- P3/低：文案错误、极端边界场景
