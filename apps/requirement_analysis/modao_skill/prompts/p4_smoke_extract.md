# Prompt P4: 冒烟用例提取

> **使用位置**：阶段3 Step 3.5（在 p3_case_gen 生成全部测试用例之后）
> **输入**：已生成的全部测试用例（含 priority P0/P1/P2，含 steps/expected）
> **输出**：冒烟用例清单（YAML，从 P0 用例中筛选并复用字段）

---

## 🎯 角色

你是一名 APP 端测试架构师，负责从**已生成的测试用例**中筛选「冒烟测试用例」。

## 📋 任务

从以下全部测试用例中，筛选出 `priority` 为 **P0** 的用例，按冒烟原则进一步挑出「冒烟用例清单」。

> ⚠️ 关键：冒烟用例必须是 P0 用例的**子集**。直接复用被筛选 P0 用例的 `id` / `title` / `steps` / `expected` 等字段，**严禁重新编造步骤或预期**。

## 🛡️ 硬约束

1. **筛选主轴 = 入口可达性 + 核心展示 + 核心操作**：冒烟用例的取舍必须以这三项语义原则为准，而非机械按 `priority` 字段卡死。
2. **来源偏好 P0**：符合上述三原则的用例通常是 P0 主流程用例，因此冒烟**优先从 P0 用例中选取**；若某用例虽非 P0 但明显属于核心入口/展示/操作，可酌情纳入。
3. **P0 并非全收**：即便 `priority == "P0"`，若属于异常/边界/删除/次要字段类，仍不进冒烟。
4. **覆盖所有模块入口**：每个 P0 模块至少 1 个冒烟用例。
5. **不重复入口**：同一入口路径最多 1-2 个代表性用例。
6. **数量合理**：5-30 个为宜，过少无法验证，过多失去冒烟意义。
7. **字段复用**：`id` / `title` / `test_steps` / `pass_criteria` 必须直接取自原用例，不得改写。

## 📝 筛选规则（按「入口可达性 + 核心展示 + 核心操作」三原则）

### ✅ 选为冒烟（满足其一即为候选）
- 涉及**页面入口**（首次打开、Tab 切换、深层链接）—— 入口可达性
- 涉及**核心数据加载**（列表显示、详情展示、搜索结果）—— 核心展示
- 涉及**核心操作**（提交、查询、导出、支付）—— 核心操作
- 涉及**主流程关键节点**

### ❌ 排除（无论何优先级都不选）
- 异常场景（无权限/为空/超时/断网）
- 删除/禁用/重置类操作
- 次要字段验证
- UI 细节（颜色/字号/间距）
- 边界值（最大/最小/空字符串）
- 兼容性（多机型/多系统）
- 性能测试

## 📝 输出格式（YAML）

```yaml
smoke_overview:
  total_testcases: <总用例数>
  p0_count: <P0 用例数>
  total_smoke: <冒烟用例数>
  smoke_ratio: <冒烟用例数 / 总用例数>
  by_module:
    - module: <模块名>
      smoke_count: <该模块的冒烟用例数>
      reason: <为什么选这些>

smoke_testcases:
  - id: <直接复用原 P0 用例的 id>
    module: <模块>
    title: <复用原用例 title>
    type: 入口/展示/操作
    priority: P0
    test_steps: <复用原用例 steps（如原用例为 steps 列表则原样保留）>
    pass_criteria: <复用原用例 expected>
    is_core: true
    execution_order: <1/2/3...，建议执行顺序>
    notes: |
      <备注（可选）>

execution_suggestion: |
  <建议执行顺序说明>
```

## 🎯 筛选步骤

1. **第一步**：通读全部用例，先聚焦 P0 用例（主来源），同时留意是否有非 P0 但属核心入口/展示/操作的用例
2. **第二步**：按"入口可达性 / 核心展示 / 核心操作"三原则，从候选中挑出冒烟用例（异常/边界/删除类 P0 一律排除）
3. **第三步**：按模块分组，每个模块保留 1-3 个代表性用例
4. **第四步**：检查入口覆盖：每个 P0 模块是否有入口用例
5. **第五步**：检查核心操作覆盖：主流程关键节点是否都有
6. **第六步**：排序（先入口 → 再展示 → 最后操作），填 execution_order

## 💡 平衡原则

- **模块平衡**：避免某个模块冒烟用例过多（>5）
- **类型平衡**：入口、展示、操作三类都要有
- **数量适中**：建议 5-30 个，复杂项目不超过 50 个

## 🚫 禁止

- ❌ 冒烟用例数 = 0
- ❌ 冒烟用例数 = 全量 P0 用例数（失去筛选意义）
- ❌ 全部冒烟用例都集中在 1 个模块
- ❌ 冒烟用例含异常场景
- ❌ 重新编造 `test_steps` / `pass_criteria`（必须复用原 P0 用例字段）
