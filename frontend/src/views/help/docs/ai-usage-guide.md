# AI 用例生成 · 操作使用说明

这条线是**「给一段需求 → AI 直接产出测试用例」**，适合已有文字需求、需求文档或需求截图的场景。
如果你手上只有**磨刀原型链接**，请改用「墨刀原型解析」那条线（入口在首页同一个模块里，文档见左侧「墨刀原型解析」分组）。

## 一、入口

首页卡片 **「AI用例生成」** → 进入 `/ai-generation/requirement-analysis`，页面标题为「智能测试用例生成」。

首次进入会弹「开始使用AI用例生成功能」引导窗，列出模型 / 提示词 / 生成配置是否就绪。缺哪个点「去配置」跳过去补，也可以「稍后配置」直接开跑（用默认配置）。

## 二、整体流程

页面顶部是 4 步步骤条：**1 需求分析 → 2 用例编写 → 3 用例评审 → 4 完成**。

> 第 3 步「用例评审」是条件显示的。如果在「提示词配置 → 生成行为配置」里关掉了「启用AI评审和改进」，步骤条就只有 3 步——这不是 bug，是配置决定的。

## 三、四种输入方式（都在同一页，从上往下排）

| 方式 | 区域标题 | 支持格式 | 说明 |
| --- | --- | --- | --- |
| 手输/粘贴 | ✍️ 手动输入需求描述 | 纯文本 | 最常用，标题+描述必填 |
| 上传文档 | 📄 上传需求文档 | `.pdf` `.doc` `.docx` `.txt` `.md` | 可拖拽，**必须再填「文档标题」** |
| 需求文档生成 | 📋 需求文档生成 | 粘贴文字 / 上传文件 | 先把原始材料整理成规范文档，再由文档生成用例；图片型 PDF 会显示「👁️ AI 视觉识别并生成文档」 |
| 需求截图 | 需求截图（可选，支持多模态分析） | `image/*`，可多张 | **只在做需求拆解之前可传**，一旦有拆解结果该区域就消失 |

选错文件格式会提示「请选择 PDF、Word、TXT 或 Markdown 格式的文件」。

## 四、操作步骤

### 第 1 步 · 填需求

- **需求标题**（必填），如「用户登录功能需求」
- **需求描述**（必填），下方示例给了 5 条参考写法
- **关联项目 / 关联版本**（可选），版本右侧有 `+` 可快速新建
- 右下角实时显示字数，**超过 5000 字**才提示「建议不超过 5000 字，过长请分段」

> 字数没有硬拦截，但超长需求受模型上下文限制，实际效果会下降——建议分段生成。

### 第 2 步 · 点生成

点 **「🚀 生成测试用例」**（上传文档时按钮在文档区，写完标题才亮）。

旁边还有 **「🧩 需求拆解」**：先把需求拆成结构化模块再生成，质量更高，但会多一道确认（见「常见坑」第 1 条）。

### 第 3 步 · 确认弹窗

弹出「🚀 生成测试用例」确认窗，需要填：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 生成模式 | **必填** | 四选一，决定用例条数（见下表） |
| 归属项目 | **必填** | 决定知识库从哪读 |
| 关联版本 | **必填** | 可选「不关联版本」 |
| 功能模块 | 选填 | 带 `+` 快速新建 |
| 测试点 | 选填 | **必须先选功能模块**，`+` 才可用 |

**生成模式四选一：**

| 模式 | 说明 | 大致条数 |
| --- | --- | --- |
| 🤖 智能 / AI评估 | 由 AI 判断需求复杂度决定规模 | 不定 |
| ⚡ 快速 | 快速摸底 | 10~20 条 |
| 📋 标准 | 常规覆盖 | 20~40 条 |
| 🔬 全面 | 全量覆盖 | 更多 |

项目和版本都选了之后 **「✅ 确认并开始生成」** 才可点。

### 第 4 步 · 等待生成

页面切成「🤖 AI正在为您生成测试用例」卡片，显示：

- 顶部：当前模式徽章 + 任务 ID + 当前状态
- 三个流式区域：**✍️ 实时生成内容** / **📝 AI评审意见** / **🎯 最终版用例**，各带字符计数
- 状态文案依次是：`正在创建生成任务...` → `任务已创建，正在处理中...` → `正在编写测试用例... N%` → `正在评审测试用例... N%` → `🎯 正在流式生成最终版用例...` → `生成完成！`

输出模式可在页面顶部切换 **⚡ 实时流式输出** / **📄 完整输出**，默认值在生成行为配置里改。

用的是 SSE 流式推送，断线会自动提示「流式连接中断，切换到轮询模式」并继续跑，不用管。

中途不想等了，点 **「取消生成」** 会通知服务端停止，后续步骤不再消耗 token。注意：**直接关闭页面不会停止任务**，必须点这个按钮。

**耗时参考**：评审/改进阶段后台超时按配置的「评审和改进超时时间」（10~3600 秒）控制，界面提示「预计 30-60 秒完成」。

### 第 5 步 · 处理结果

生成完出现三个按钮：

| 按钮 | 作用 |
| --- | --- |
| 📥 下载测试用例 | 导出 xlsx，表头：测试用例编号 / 测试场景 / 前置条件 / 操作步骤 / 预期结果 / 优先级 |
| 💾 保存到用例库 | 入库，之后可在用例库统一管理 |
| 📝 生成新用例 | 清空重来 |

## 五、评审与反馈（重点）

用例生成完，去**任务详情页**做评审和修正。入口：历史任务列表点「👁 详情」，或直接访问 `/ai-generation/task-detail/:任务ID`。

详情页头部四个按钮：

| 按钮 | 出现条件 | 作用 |
| --- | --- | --- |
| 🔄 重新评审 | 已完成 | 用最新评审规则重评，**保留现有用例，只更新评审报告** |
| 🔄 基于调整重新生成 | 已完成且有评审反馈 | 按评审意见+你的回复生成改进版，**会覆盖** |
| 🆕 从头重新生成 | 已完成 | 完全重来 |
| 💾 导出Excel | 已完成 | 导出结构化用例表 |

### 逐项确认回复

「AI 评审报告」卡片默认展开，标题带「第 N 次评审」。下方 **💬 逐项确认回复** 区域会列出不确定的需求点，AI 自动识别出来的带 🤖 标记，横幅提示「🤖 AI已自动识别 N 个不确定项，请逐一回复确认」。

每条要填两栏：

- **不确定需求**（最多 300 字），如「截屏后是否支持编辑？」
- **确认回复**，如「已确认，V1.0 暂不支持编辑，V2.0 再上」

填完点保存，提示「已保存 N 项确认回复」；一条都没填会报「请至少添加一项确认内容」。已回复的会折叠成「✅ 已确认项（N 条）」。

然后点 **✅ 确认重新生成**，弹窗会明确警告：

> ⚠️ AI 将根据评审报告的意见，结合你逐项确认的回复，重新生成改进版测试用例。重新生成会**覆盖当前的用例内容**，原内容将无法恢复。

## 六、历史任务列表

`/ai-generation/generated-testcases`，列：任务ID / 关联需求 / 关联版本 / 功能模块 / 状态 / **评审结果** / 用例条数 / 生成时间 / 操作。

行操作：**👁 详情**、**✅ 采纳**、**❌ 弃用**、**🚀 转UI自动化**、**🗑️ 删除**（后几个只在「已完成」状态可用）。顶部支持批量删除。

点「✅ 采纳」会弹窗让你改：用例标题（必填）、优先级（低/中/高/紧急）、测试类型（功能/集成/API/UI/性能/安全）、状态（草稿/激活）、前置条件、操作步骤、预期结果、评审意见。

**状态中文对照**：`pending` 需求分析中 / `generating` 用例编写中 / `reviewing` 用例评审中 / `revising` 用例改进中 / `completed` 已完成 / `cancelled` 已取消 / `failed` 失败。
**评审状态**：🔘 未评审 / ✅ 通过 / ⚠️ 待确认 / ✔️ 已确认。

## 七、常见坑（务必看）

1. **待确认项会锁死生成按钮**：做过「需求拆解」且有未确认项时，「🚀 生成测试用例」会置灰，提示「请先在拆解结果中逐项确认所有待确认项」。**没做拆解的用户不受影响**。
2. **确认弹窗里项目和版本是硬必填**，不选按钮点不动。
3. **「取消生成」会真正停止后端**：点了之后前端会通知服务端，后台线程在流式输出过程中和阶段之间检查到取消信号就停止，不再继续调用模型，任务状态变成「已取消」，后续步骤的 token 不会消耗。但有两点要注意：① 已生成的部分内容**不会**作为结果保留（取消即丢弃，用例列表里看不到半成品）；② **直接关闭浏览器页面不会取消任务**，任务会照常跑完——要真正停必须点「取消生成」。
4. **重新生成不可逆**，弹窗原文写的是「原内容将无法恢复」。
5. **上传文档必须填标题**，不填按钮置灰；文档内容为空会报「无法从文档中提取到有效内容，请检查文档格式」。
6. **需求截图只在拆解前能传**，有拆解结果后上传区消失。
7. 没有独立的「重试」按钮，失败后用详情页「🆕 从头重新生成」，或在列表里删掉重来。
8. **没有「启用知识库」勾选框**：知识库靠「关联项目」隐式触发。选了项目就提示「将读取该项目知识库辅助生成」，且你确认过的问答会**自动回填到项目知识库**（提示「已自动补充 N 条知识到项目知识库」）。不想污染知识库就别关联项目。
9. 页面没有「生成数量」「并发数」控件，用例规模由生成模式间接控制。
10. 用例步骤缺失会在详情页标红「步骤缺失，请补充操作步骤」，这类建议补完再采纳。
