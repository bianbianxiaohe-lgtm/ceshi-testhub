# 墨刀原型解析 · 操作使用说明

这条线是**「给一个磨刀原型链接 → AI 读懂页面 → 跟你确认疑点 → 产出测试用例」**，适合**只有原型、没有文字需求**的场景。
如果你已经有文字需求或需求文档，用「AI用例生成」那条线更快（文档见左侧「AI 用例生成」分组）。

## 一、入口

首页 → **「墨刀需求分析」** → `/ai-generation/modao-skill`（任务列表页）。

点右上角 **「+ 新建需求任务」** 进入工作页 `/ai-generation/modao-canvas/new`，页面标题「🧩 墨刀需求读取与用例生成」。

## 二、五阶段总览

顶部是 5 步步骤条：

| 步骤 | 名称 | 你要做的事 |
| --- | --- | --- |
| 阶段 0 | 原型接入 / 墨刀逐页读取 | 填链接，让系统去读页面 |
| 阶段 1 | 需求通读 / 结构化摘要 | 核对画布、生成需求摘要 |
| 阶段 2 | 需求澄清 | **逐条回答 AI 提出的问题** |
| 阶段 3 | 用例设计 | 合并测试点、生成用例 |
| 阶段 4 | 冒烟执行 | 执行决策 |

页面是**3 秒轮询**刷新（不是流式），切走页面不影响，跑完回来看即可。

## 三、阶段 0 · 填链接开始读取

### 选需求来源（三选一）

| 来源 | 说明 |
| --- | --- |
| 墨刀原型链接 | 磨刀分享地址，一行一个 |
| webshare 页面树链接 | 目录地址，系统自动枚举目录下所有页面 |
| 需求文本/文档 | 直接粘贴需求正文 |

### 填写字段

- **需求地址**：每行一个。`https://modao.cc/proto/xxxx/sharing?view_mode=read_only`
- **webshare 页面树链接**：每行一个目录地址，系统自动展开
- **登录 Cookie**（选填）：原型需要登录才能看时必填，否则抓不到内容
- **需求文本**：文本来源时粘贴正文
- **标题**：默认「墨刀需求梳理」
- **归属项目**：建议一开始就选，不选会导致后面无法同步功能模块、无法采纳到用例库
- **关联版本**（可选）
- **双路融合**（默认开启）：DOM 与视觉分别逐页提取，再由 AI 交叉融合。任一路覆盖不足会阻断后续，避免生成不完整用例——**建议保持开启**

> **不支持上传原型文件**，全流程只认链接。唯一的上传是阶段 1 的 `.xmind`（用于覆盖结构化摘要）。
> 地址里含 `/webshare/` 会自动改判为 webshare 来源。

点 **「开始读取墨刀」**（webshare 来源显示「开始读取 webshare 页面树」，文本来源显示「保存需求文本」）。

运行中显示 **「终止任务」**，确认弹窗会提示「已产生的部分结果会被标记为失败」。

**耗时**：按画布数量线性叠加，量级从几分钟到几十分钟。整轮跑完前请保持页面打开或稍后回来查看。

## 四、阶段 0.5 · 画布模块校验

读完之后会出现「画布模块校验 · 选择参与需求结构化的画布」：左边列表右边预览，预览显示截图分段缩略图、识别文本、注释标注、提取警告。

每条画布可以：改名、填父级分组、标记**识别准确率**（准确 / 基本准确 / 偏差较大 / 需重读）。

- **至少要勾选一个画布**
- 改完必须点 **「保存校验结果并进入需求结构化」**，不保存后端会回退成全选——会出现「明明只选了 1 个、摘要却是整个版本」的情况
- 标记「偏差较大 / 需重读」的画布结果不可信，建议人工校正后重读

## 五、阶段 1 · 需求通读

点 **「运行需求结构化」** 生成需求摘要，产出后可以看 `👁️ 预览 XMind`、`⬇️ 下载 XMind`，也可以用 `⬆️ 上传 XMind` 覆盖系统生成的摘要。

确认无误后点 **「确认摘要，进入阶段 2」**。

## 六、阶段 2 · 需求澄清（最关键，不能跳过）

点 **「识别澄清问题」**，系统会列出 AI 识别出的问题。每张卡片包含：类型标签（模糊点 / 缺失点 / 边界点）、优先级、📍 位置、问题描述、建议提问、影响范围。

**这是自由文本输入，没有选项，也没有字数限制**，placeholder 是「填写与产品确认后的回复/结论…」。

你需要**拿着这些问题去问产品**，拿到结论后回来逐条填。

- 填完点 **「💾 保存全部回复」**，提示「澄清回复已保存」
- 还有 **「✏️ 编辑原文」/「✏️ 编辑逐条」** 两种模式可切换

### 不填完会怎样

黄色告警：**「还有 N 条位置/需求问题未填写人工结论，不能进入最终用例生成流程」**，且 **「已与产品确认，进入阶段 3」按钮直接置灰**。

强行调接口会返回 409。也就是说——**这一步不能跳过**。

> 改完澄清内容后，之前的「批准生成」会失效，提示「内容已变更，原『批准生成』已失效，需重新批准后再生成最终用例」，需要再批准一次。

## 七、阶段 3 · 用例设计

确认进入后有两个按钮，**必须按顺序点**：

1. **① 运行测试点合并** —— 先把各画布的测试点合并去重
2. **② 确认测试点，生成测试用例** —— 状态就绪且已有合并测试点才可点

> 没跑第 1 步直接点第 2 步会报「请先运行测试点合并（第一段），生成最终测试点后再生成用例」。

点第 2 步会弹人工批准确认：

> 请确认：所有位置、交互和需求疑问均已由人工给出结论，且当前合并测试点可用于生成最终测试用例。确认后系统会记录批准人和当前内容指纹；后续编辑会使本次批准失效。

点 **「确认并批准生成」**。

### 产物查看

阶段 3 上方有筛选标签：**全部 / 模块拆分 / 风险识别 / 待确认问题 PCI / 合并测试点 / 测试用例 / 冒烟用例 / 质量报告**。

## 八、交付

- **⬇️ 下载 Excel（按模块分 sheet）**
- **📥 采纳到用例库** —— 未关联项目时提示「请先在阶段0关联项目，再采纳到用例库」

## 九、任务列表与状态

列表列：标题 / 来源 / 状态 / 进度（阶段 N · 阶段名）/ 创建人 / 更新时间 / 操作。点行可展开看**工作日志**和**错误信息**。

**状态中文对照**：

| 状态 | 含义 |
| --- | --- |
| 待处理 | 刚创建 |
| 读取中 | 正在逐页读原型 |
| 已读取 | 读取完成 |
| 部分读取 | 只拿到部分画布，需要续读 |
| 结构化中 | 生成需求摘要 |
| 澄清中 | 生成澄清问题 |
| 用例设计中 | 合并测试点/生成用例 |
| 已完成 | 全部跑完 |
| 失败 | 出错，展开看错误信息 |

**行操作**：

| 按钮 | 说明 |
| --- | --- |
| 继续 | 「部分读取」时变「继续读取」 |
| 重走 | **退回第一步重来，会清空**（见下方坑 6） |
| 删除 | 删除整条任务 |

**失败重试入口**：工作页的「重新读取当前任务」/「继续读取（补齐剩余画布）」、列表页的「重走」、阶段 1 的「重新结构化全部」（强制重跑所有画布，耗时和费用更高）。

重跑默认**增量跳过已完成的画布**，提示「已完成的画布会自动跳过，不会重复消耗模型」；只有「重新结构化全部」会全量重跑。

## 十、常见坑（务必看）

1. **不支持上传原型文件**，只能填 URL。
2. **多个链接必须一行一个**，不能逗号分隔（后台会把逗号转成换行，但建议直接换行更稳）。
3. 只填目录地址依赖页面树自动发现，识别不到就只拿到部分页面——建议直接贴具体页面链接。
4. **需要登录的原型必须填 Cookie**，否则抓不到内容。
5. **澄清必须逐条填完**，否则「进入阶段 3」永久置灰，后端 409 拦死。
6. **「重走」会清空**：读取结果 + 结构化内容 + 澄清答案 + 测试点 + 用例全部清掉。弹窗原文确认会提示「已采纳到用例库的数据不会删除」。
7. 必须先跑 **① 运行测试点合并** 才能跑 **②**，顺序不能反。
8. **阶段 0 不选项目** → 摘要不同步功能模块、后面无法采纳到用例库。
9. **画布至少勾 1 个，且勾选后必须保存**，否则后端回退全选。
10. **partial（部分读取）状态要去工作页**点「继续读取（补齐剩余画布）」，看板页没有续读入口。
11. 依赖视觉/截图识别，标记「偏差较大 / 需重读」的画布结果不可信，需人工校正后重读。
12. 运行中按钮全部禁用，页面 3 秒轮询一次，切走也没关系。

## 十一、看板页

`/ai-generation/modao-board/:id` 是「📂 画布任务看板」，按文件夹分组展示画布卡片：缩略图、`P{页码}`、阶段标签、进度百分比、识别摘要、错误信息，可「进入当前阶段」或「查看产物」。
