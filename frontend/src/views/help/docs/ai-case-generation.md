# AI 用例生成 · 模型配置与调用流程

这条线指「AI用例生成 → 需求分析 → 生成测试用例」，入口是 `TestCaseGenerationTaskViewSet.generate`。
**磨刀原型解析是另一条独立的线，配置不通用，请看另一篇文档。**

## 一、需要配哪些角色

用例生成只会用到下面前四种角色，括号里是代码中取配置的位置。

| 角色 | 用途 | 是否必需 |
| --- | --- | --- |
| writer | 测试用例编写专家，真正生成用例正文的模型 | **必需** |
| reviewer | 测试评审专家，对生成的用例挑错并抽出待确认项 | 可选 |
| analyzer | 需求拆解专家，前置分析需求、补充上下文 | 可选 |
| embedder | 向量化模型，把需求转成向量去知识库召回资料 | 可选 |
| writer_vision | 视觉分析，截图/图片/PDF 解析 | 本条线不用（磨刀线用） |
| reranker | 重排序，提升知识库召回精度 | 暂未启用 |

同一个角色可以有多条配置，但只有启用状态的那条生效，且系统只取其中一条。
**建议每个角色只保留一条启用**，多余的一律停用，否则取到哪条是不确定的。

## 二、调用顺序

整个流程串行执行，共 7 步：

| # | 步骤 | 角色 | 作用 | 代码位置 | 必需 | 失败会怎样 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 需求拆解 | analyzer | 先分析需求，结论作为已知信息注入第 4 步 | `views.py:1421` | 否 | 跳过，直接用原始需求生成 |
| 2 | 绑定模型 | writer + reviewer | 取出配置挂到任务上，**不发请求** | `views.py:1495 / 1514` | 是 | 取不到直接报错 |
| 3 | 知识库语义检索 | embedder | 向量化需求，从知识库召回相关资料 | `ai_model_service.py:307` | 否 | 降级为知识库全量灌入 |
| 4 | 生成测试用例 | writer | 流式生成用例正文 | `ai_model_service.py:1454` | 是 | 任务失败 |
| 5 | 用例评审 | reviewer | 评审并抽出待确认项 | `ai_model_service.py:1556` | 否 | 保留未评审的原始用例 |
| 6 | 按评审意见改写 | writer | 按评审结果重写用例 | `ai_model_service.py:1655` | 否 | 回退到改写前的版本 |
| 7 | 人工反馈二次改写 | writer | 补充反馈后重跑，或确认后重新评审 | `views.py:1945 / 2989` | 否 | 不触发即结束 |

第 4 步生成完还有去重、补尾、限制条数等处理，这些是纯规则计算，**不调用模型、不消耗 token**。

## 三、最容易填错：Key 与地址必须同源

API Key 和 Base URL 必须来自同一个服务商，否则直接返回 `401 invalid_api_key`。

| Key 前缀 | 服务商 | Base URL | 支持 embedding |
| --- | --- | --- | --- |
| `sk-sp-` | 阿里云 token-plan | `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` | 不支持 |
| `sk-ws-` | 阿里云百炼（官方） | `https://dashscope.aliyuncs.com/compatible-mode/v1` | 支持 |
| `sk-`（35 位） | DeepSeek 官方 | `https://api.deepseek.com` | 不支持 |

> **注意**：token-plan 的 Key 不授权 embedding 模型。向量化（如 text-embedding-v3）必须配官方百炼地址，否则即使 Key 本身有效也会报错。

## 四、常见报错对照

| 报错信息 | 原因 | 怎么处理 |
| --- | --- | --- |
| `401 Invalid API-key provided` | Key 与 Base URL 不同源，或 Key 已失效/被删除 | 按上一节核对组合；换环境复用 Key 前先确认还在有效期 |
| `404 Unsupported model ... for OpenAI compatibility mode` | 拿聊天接口去测向量化模型 | 向量化配置请用页面上的「测试连接」，它会自动走 embeddings 接口 |
| `连接测试超时` | 网络不通或地址写错，60 秒无响应 | 确认服务器能访问该域名，地址末尾不要多带路径 |
| 用例能生成但不参考知识库 | embedder 失效，已静默降级为全量灌入 | 检查向量化配置的测试连接是否通过 |
| 评审/改写步骤没生效 | 未开启自动评审，或 reviewer 没启用 | 检查开关与 reviewer 配置的启用状态 |

## 五、可选步骤失败的表现

这几步即使模型不可用流程也不会中断，是「能跑通但结果不对」最常见的原因。

| 步骤 | 失败后的表现 |
| --- | --- |
| 知识库语义检索 | 改为把知识库全量塞进提示词，token 消耗上升、召回不精准，界面无报错 |
| 用例评审 | 跳过评审，直接产出未评审的用例 |
| 按评审改写 | 回退到改写前的版本，等于评审白做 |
| 需求拆解 | 不补充上下文，直接按原始需求生成 |

## 六、其它

- 磨刀原型解析是独立的一条线，用自己的 analyzer / writer / embedder 配置，与本流程互不影响。
- `reranker` 角色已定义，但本流程暂未启用，目前只有禅道覆盖分析在用。
- `browser_use_text` / `midscene_vision` 服务于 UI 与真机自动化，不参与用例生成。
